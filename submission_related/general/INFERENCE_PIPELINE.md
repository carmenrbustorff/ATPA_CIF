## Task 1: Dynamic inference.py Generation in agent.py

### What Changed
agent.py now automatically generates a Kaggle-ready inference.py script alongside every train.py.

### Implementation Details

1. **KAGGLE_INFERENCE_TEMPLATE** (agent.py, line ~69)
   - Global string constant containing the full inference pipeline
   - Features:
     - CPU-to-GPU memory-efficient audio processing
     - 5-second sliding windows at 32kHz sample rate
     - Log-mel spectrogram extraction on CPU (avoiding GPU overhead)
     - Batch inference with torch.autocast() for mixed precision
     - Immediate GPU memory cleanup with torch.cuda.empty_cache()
     - Pandas left-join logic for 206→234 class mapping
   - Placeholder: {INJECTED_MODEL_CLASSES} - auto-filled with extracted model classes
   - Placeholder: {NUM_LOCAL_CLASSES} - auto-filled with 206

2. **extract_model_classes()** Function (agent.py, line ~652)
   - Uses Python's AST module to parse generated train.py
   - Finds all class definitions that inherit from nn.Module
   - Extracts raw source code of these classes
   - Returns concatenated source as a string ready for injection

3. **Integration in propose_and_generate_code()** (agent.py, line ~926)
   - After LLM generates train.py:
     - Extracts model classes with extract_model_classes()
     - Formats KAGGLE_INFERENCE_TEMPLATE with extracted classes
     - Finds the model class dynamically (using inspect)
     - Writes inference.py to iteration_dir / "inference.py"

### Generated Script Structure
Each iteration_dir now contains:
  - train.py       (training script, generated by LLM)
  - inference.py   (inference script, auto-generated from model classes)
  - best_model.pth (model weights, written by train.py)
  - metrics.json   (training metrics)

### Key Algorithm Details

#### Audio Processing Pipeline (in inference.py):
1. Load audio file with soundfile.read() on CPU
2. Resample to 32kHz if needed
3. Split into 5-second windows (160,000 samples @ 32kHz)
4. For each window:
   a. Extract log-mel spectrogram on CPU (MelSpectrogram transform)
   b. Move only the spectrogram tensor to GPU
   c. Run model inference with torch.autocast()
   d. Move predictions back to CPU
   e. Delete GPU tensors and call torch.cuda.empty_cache()
5. Aggregate window predictions using max pooling per class
6. Merge with Kaggle submission template (206 classes → 234 classes via left-join)
7. Fill missing classes with 0.0
8. Save as submission.csv

#### Class Extraction Logic (in extract_model_classes):
- Parses AST of generated train.py
- Identifies classes that inherit from nn.Module
- Extracts lines from node.lineno to node.end_lineno
- Concatenates all model classes into a single string
- Returns this string for injection into inference template

## Task 2: generate_local_submission.py Utility

### What Is It
A standalone Python script that:
- Tests dynamically generated inference.py before Kaggle submission
- Runs inference on a local test audio directory
- Validates submission CSV format
- Saves validation report

### CLI Interface

```bash
python generate_local_submission.py \\
    --iteration-dir /path/to/iteration/folder \\
    --test-audio-dir /path/to/test/audio \\
    --output-dir ./submissions/
```

### Arguments
- `--iteration-dir` (required): Path to iteration folder containing:
  - inference.py
  - best_model.pth or model.pt
  
- `--test-audio-dir` (required): Path to directory with audio files
  - Supported formats: .ogg, .wav, .flac, .mp3
  
- `--output-dir` (optional, default: ./submissions/): Output directory for submission.csv

### Execution Flow

1. **File Verification**
   - Checks that inference.py and best_model.pth exist
   - Checks that test_audio_dir exists

2. **Dynamic Module Loading**
   - Uses importlib.util.spec_from_file_location()
   - Loads inference.py as a module without requiring it to be in sys.path
   - Calls the module's generate_submission_csv() function

3. **Error Handling**
   - Catches and logs all exceptions with full stack traces
   - Allows inference failures without crashing the script

4. **CSV Validation**
   - Loads output submission.csv with pandas
   - Validates:
     - Exactly 235 columns (1 row_id + 234 species columns)
     - First column is named "row_id"
     - No NaN values in any cell
     - All numeric columns are numeric type
   - Saves validation_report.json with detailed results

### Output Files
In output_dir:
- `submission.csv`: Generated Kaggle submission
- `validation_report.json`: Detailed validation results

### Validation Report Structure
```json
{
  "file_exists": true,
  "shape": [100, 235],
  "columns": 235,
  "first_column": "row_id",
  "has_nan": false,
  "nan_count": 0,
  "is_valid": true,
  "errors": [],
  "warnings": []
}
```

### Example Usage

```bash
# Test iteration 150 with local test audio
.venv/bin/python generate_local_submission.py \
    --iteration-dir ./experiments/iterations_0151-0200/iter_0150_20260518_100000 \
    --test-audio-dir ./test_audio_samples \
    --output-dir ./local_submissions

# Check the validation report
cat ./local_submissions/validation_report.json
```

## Error Handling

### Common Issues and Solutions

1. **No model classes found in train.py**
   - Solution: Ensure train.py defines at least one class inheriting from nn.Module
   - Check: grep "class.*nn.Module" train.py

2. **inference.py module won't load**
   - Check syntax: python -m py_compile inference.py
   - Check imports: Are all required modules available in the venv?

3. **Validation fails: wrong column count**
   - Likely cause: Model class not found during inference
   - Check inference.py's class detection logic
   - Manually verify BirdCLEFModel is in injected code

4. **GPU out of memory during inference**
   - The 5-second window + batch_size=16 should fit on most GPUs
   - If still OOM: reduce BATCH_SIZE_INFERENCE in inference.py template
